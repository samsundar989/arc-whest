# E14: a connected-tree K4 regeneration definition

**Symbolic follow-up, September 14. No numerical experiments performed.** This
supplies one explicit *approximate* missing closure from the
[preceding derivation](2026-09-14_e14_accuracy_derivation.md). It is neither a
stability result nor an accepted candidate. The previous inability to reconstruct
an exact tensor from readout slices does not prohibit this declared approximation.

The distinction from the previous failed implementation is concrete: regenerate
the off-diagonal fourth-cumulant contraction from connected Gaussian tree
diagrams on the current F21 preactivation, instead of setting it proportional to
covariance or carrying a one-time synthetic bank through raw linear maps. The
external author ablations motivate consistent use and feed, not the correctness
of this proposed formula. The earlier failed implementation does not scientifically
close the covariance-alignment family.

**Result of this derivation:** the closure can be defined consistently and its
matrix contraction costs four square products per birth. Its required persistent
K3 feed is substantially more expensive than the matrix core. A straightforward
uncompressed implementation remains above the live FLOP budget even with the
specified final-layer pruning. Exact sharing or a separately declared compression
may change that bill; no lower-bound impossibility, stability, accuracy or net
score claim follows. No production implementation should start before independently
checking the equations and a complete cheaper program.

## 1. Dense definition, including repeated indices

Use F21's `B=W.T`, current preactivation covariance `C`, and its actual coefficient
vectors

`b_i=w_i(1,1)`, `a_i=w_i(2,1)`, `d_i=w_i(3,1)`.

In the formal unsaturated Gaussian interpretation these are the first three
expected ReLU derivatives. An executable candidate retains F21's alpha clipping
and variance floor exactly, so this interpretation is qualified wherever either
policy changes the coefficients. Neither a new saturation nor damping is part of
this definition.

The symbolic equations assume symmetric covariance/core matrices. In floating
point, define the **new closure's** `C=(Cpre+Cpre.T)/2`, and symmetrize each
new transported/generated `G` and `M` by the same average. Leave the original
F21 mean/covariance calculation and its inputs to existing consumers unchanged.
These explicit `O(n^2)` averages belong in the incremental ledger; they ensure
tensor symmetry, not PSD, and do not repair a negative variance.

For four **labelled vertices** `1,2,3,4` assigned coordinate indices
`i1,i2,i3,i4`, define

```
Ttree_i1i2i3i4 = sum over the 16 labelled spanning trees tau:
                product_v w_iv(degree_tau(v),1)
                * product_{(u,v) in edges(tau)} C_iu,iv.
```

Four trees are stars (one `d`, three `b` coefficients); twelve are paths (two
`a`, two `b`). Each labelled tree occurs once. There is no extra factorial.
Indices may coincide: retain distinct vertex labels and use `C_ii` on an edge
whose endpoint coordinates coincide. This convention defines repeated entries
without taking an off-diagonal formula into an undefined limit.

This is the connected Gaussian diagram contribution with exactly three edges.
It omits connected multigraphs with more edges and incoming non-Gaussian diagrams.
For repeated coordinate indices, the corresponding correlation is one, so an
expansion in small cross-correlations provides **no** small-remainder guarantee.
This motivates anchoring the repeated contractions already supplied by F21,
rather than treating the unmodified tree polynomial as accurate at repeats.

After the layer's complete extra-K4 consumer update and unchanged F21 centering,
let `k4_i=K[(4,)]_i` and define the new closure's anchor
`k22=offdiag((K[(2,2)]+K[(2,2)].T)/2)`. The original F21 consumers
keep their unsymmetrized corrected K22. Count this extra average; it removes
roundoff ambiguity between permutations of the new tensor only.
Define a symmetric dense *target* tensor `Tstar` by equality pattern:

```
all four coordinates equal i:             Tstar_iiii = k4_i
two pairs, distinct i,j:                   Tstar_iijj = k22_ij
all other equality patterns:               Tstar = Ttree.
```

The two-pair assignment applies to every permutation. The remaining patterns
are `(3,1)`, `(2,1,1)`, and `(1,1,1,1)`. This is a single explicit tensor, not
unrelated formulas for mean, covariance and feed. Its arbitrary full raw fourth
moments can be defined from this cumulant and the same output mean/covariance/K3
through the ordinary moment-cumulant partition identity. Positive representing
measure existence is not claimed.

Only the contraction of `Tstar` is retained. The anchoring is an approximation
choice; it does not mean the subsequent projected tensor preserves every `k4`
or `k22` entry individually.

## 2. Four-product contraction of the dense definition

All products below are ordinary matrix products unless `.*` is shown. Let
`v=diag(C)`, with vector products and powers elementwise, and define

```
t = (C.*C) (b*b)
Zstar = C diag(d*b*v) C
Rbb = C diag(b*b) C
Raa = C diag(a*a*v) C
E = ((C.*C) diag(a*b)) C
r = C (a*b*v).
```

There are four square products: `Zstar`, `Rbb`, `Raa`, and `E`. The two vector
products and the diagonal scales cost `O(n^2)`. With `outer(x,y)=x*y.T`,

```
Hstar_tree = C .* outer(d*t,b) + transpose(C .* outer(d*t,b))
             + 2 * outer(b,b) .* Zstar

Hpath_tree = 2 * outer(a,a) .* C .* Rbb
             + 2 * outer(b,b) .* Raa
             + 2 * (C .* outer(a*r,b) + diag(a) E diag(b)
                    + transpose(C .* outer(a*r,b) + diag(a) E diag(b)))

Htree = Hstar_tree + Hpath_tree.
```

These follow by summing `Ttree_abcc` over `c`. For paths, classify which two
labelled vertices are internal: `(a,b)` gives the first term, `(c,c)` the second,
and `(a,c)`/`(b,c)` the last two orientations, each with multiplicity two.
The equations remain defined at `a=b`; the next step overrides that diagonal.

The equality-pattern anchors affect only the contraction's diagonal:

```
H_ab = Htree_ab                 for a != b
H_ii = k4_i + sum_{j != i} k22_ij.
```

For `a!=b`, none of the `T_abcc` entries has the `(4)` or `(2,2)` pattern.
Thus this replacement is exactly `H_ab=sum_c Tstar_abcc`, not another
approximation to the dense definition. The diagonal values can use the already
computed F21 moments, without creating a dense fourth tensor.

## 3. Regeneration, discarded residual, and scalar overlap

Use the normalized isotropic tensor `R(I)` and matrix lift `L_I(G)` defined in
the preceding note. For `n!=2`, set

```
h = trace(H)/n
cnew = 3*h/(n+2)
Gnew = 6/(n+4) * (H - h*I)
Qnew = L_I(Gnew).
```

In real arithmetic, `trace(Gnew)=0`; the scalar `cnew` is exactly the applicable F21 scalar
projection of its corrected `k4/k22` slices. The retained total fourth tensor
is `cnew*R(I)+Qnew`. Its contraction equals `H` exactly. The discarded tensor is

`Enew = Tstar - cnew*R(I) - L_I(Gnew)`, with `sum_c Enew_abcc=0`.

For an actual-precision implementation, evaluate `cnew` using the frozen F21
`_proj_coef_d4_r2(n)` and `lap2_d4` expression, preserving its multiplication,
addition and reduction order on the corrected original `K[(4,)]` and
`K[(2,2)]`. Do not replace it by a reassociated trace reduction. Compute `h`
and `Gnew` from the symmetric new H as written, retaining all roundoff. Thus
scalar equivalence, trace-free G and zero residual contraction are exact
real-arithmetic identities only; finite-precision discrepancies must be
recorded by the tiny oracle, not silently zeroed or treated as bit identities.

**Discard all of `Enew` every layer**, including any diagonal anisotropy and
all-distinct information not represented by the matrix lift. No assertion that
this residual is small in future queries is made. Existing residual witnesses
show why zero present contraction does not bound future D4 or birth error.
This is the one declared fourth-order projection approximation, in addition to
the declared tree truncation/anchors. It is not exact causal K4 propagation.

At width two retain the frozen zero scalar-projection fallback and disable this
extra closure; this avoids silently changing the known shape behavior. Tiny
validation must force the extra branch at widths three/four and separately check
the width-two baseline path. The target width 1024 has no such bypass.

Initialize `G=0` for the Gaussian network input. Between each nonlinear layer
and the next preactivation, transport the **two metric legs** exactly:

```
Gpre = B G B.T
Mpre = B B.T
Qpre = L_Mpre(Gpre).
```

Here `L_M(G)` replaces each Kronecker delta in the six-term lift by `M`.
F21's existing scalar preactivation approximation remains
`cold*init_scale^2*R(I)`; it is not replaced by `cold*R(B B.T)`. This deliberately
retains the baseline scalar rule while transporting only the declared extra
component exactly. Any nonzero double trace acquired by `Qpre` is consumed as
part of that extra component, not subtracted again as duplicate information.
After ReLU regenerate `Gnew` from the current state and discard the old K4 core;
the previously born K3 feeds continue through all later layers.

## 4. Exact consumers and feed of the retained core

For brevity write `G=Gpre`, `M=Mpre`. The same six-term dense lift gives

```
q4_i = G_ii M_ii
q22_ij = (G_ii M_jj + G_jj M_ii + 4 G_ij M_ij)/6
q31_ij = (G_ii M_ij + G_ij M_ii)/2
Q_iijk = (G_ii M_jk + 2 G_ij M_ik + 2 G_ik M_ij + G_jk M_ii)/6.
```

Use precisely the marginal and oriented connected-power updates from section 2
of the preceding note, for **all** consumed `pK` fields; use its unchanged F21
centering and birth subtraction. Do not add these formulas to the old compact
off recurrence. At the final layer compute only the required `q4` and mean.

The extra K3 tensor `J` from the preceding note has a useful exact decomposition.
Define `U(u,S)_ijk = u_i S_jk + u_j S_ik + u_k S_ij`, with symmetric `S`, and
`SymAvg(A,P,R)` as the sum over columns of the six permutations of the three
column factors divided by six. Then

```
Gb = diag(b) G diag(b)
Mb = diag(b) M diag(b)
u = a*diag(G)
v = a*diag(M)

J = SymAvg(diag(a), diag(b) G, diag(b) M)
    + U(u,Mb)/12 + U(v,Gb)/12.
```

This reproduces all entries, including repeats: for example
`J_iii=(3/2)*a_i*b_i^2*Q_iiii`. It is not a claim that one quadratic placement
is the full ReLU response. The normalization differs from a sum over only the
three distinct placements; losing the factor of two here is a concrete mutation
for the dense oracle.

Each birth needs one generic rank-`n` triple and two vector/symmetric-matrix
terms. For any later linear or Wick map `A`, exact transport is

`(F1,F2,F3) <- (A F1,A F2,A F3)` and `(u,S) <- (A u,A S A.T)`.

The generic triple's D21 query is

`((F1.*F2) F3.T + (F1.*F3) F2.T + (F2.*F3) F1.T)/3`,

and D3 is `sum_columns(F1.*F2.*F3)`. For `U(u,S)`, D3 is
`3*u*diag(S)` and D21 is `2*u_i*S_ij+u_j*S_ii`. Apply the ordinary diagonal mask.
The factor `1/12` may remain attached to the two U terms. Subtract their full
repeated `J` slices before the existing from-dstensor birth, then append `J` once.

## 5. Complete program and cost implications

The proposed program is now defined without selecting a fitted coefficient:

1. Run F21 linear mean/covariance and all-age K3 transports; transport `G` and
   its metric using section 3.
2. Read one extra K4 tensor's slices, evaluate every extra hyperedge consumer,
   and apply the unchanged F21 centering.
3. Carry old K3 feeds, construct the new `J`, and subtract its repeated slices
   in the same birth equation used by the original tower.
4. Compute the four-product `Htree`, apply the repeated anchors, derive scalar
   and trace-free `Gnew`, and discard the declared residual.
5. On the final layer retain only mean-relevant work. Preserve every inherited
   safety/fallback policy and report failures; introduce no PSD repair.

For an explicitly priced uncompressed implementation, store each generic birth
as three dense factor matrices and each U term as one vector plus one symmetric
matrix. A live birth requires `5*n^2+2*n` numbers; all `k` births require
`k*(5*n^2+2*n)`, before co-live transports, readouts, matrix core, baseline and
kernel scratch. Streaming birth queries is possible without deleting ages.

Use the scalar arithmetic tariff `M(n)=n^2*(2*n-1)` for a plain square f32
product. Per layer with an old birth present:

- Three products carry its generic factors; three additional products query
  their D21 at nonfinal layers.
- Four products carry its two U matrices; their vector carries and repeated
  queries are `O(n^2)`. Wick diagonal scaling is also `O(n^2)`.
- The new core costs four products to regenerate, two to transport `G`, and
  one to construct `M=B B.T`. These transport products begin only after the
  first nonlinear layer.

With depth `D`, extra feeds are born at layers `1..D-2`. The direct square
spelling has

```
feed products = 7*(D-2)*(D-1)/2 + 3*(D-3)*(D-2)/2
              = (D-2)*(5*D-8)
core products = 7*(D-1).
```

Three exact pruning improvements are included before assessing feasibility:
save one generic carry for each newborn diagonal factor (`D-2` products);
at the final layer each U term needs only `diag(B S B.T)`, saving one product
per term (`2*(D-2)`); final K4 needs only diagonal `Gpre/Mpre`, saving two more
products. This yields `Nextra=(D-2)*(5*D-8)+7*(D-1)-3*(D-2)-2`, or **1069** at
depth16. The remaining work is linear maps of vectors, elementwise state,
full moment/centering updates, masks, reductions, copies/casts and bookkeeping.

For this *particular independent-square implementation*, ideal f32 Strassen
depth4 arithmetic obeys `S_0(n)=M(n)` and
`S_j(n)=7*S_(j-1)(n/2)+18*(n/2)^2`. Thus `S_4(1024)=1,301,696,512` arithmetic
FLOPs per square product, before concatenation/copy tariffs. The extra products
alone cost `1,391,513,571,328`; adding frozen F21's measured total
`928,457,637,478` gives **2,319,971,208,806**, already above `2^41`. This is
symbolic pricing, not a counted-package observation or a wall-time estimate.

This rejects that explicit square spelling at live shape. It does **not** prove
every exact implementation exceeds budget: shared metric/factor transport,
Gram representations of the U terms, or batching may change the count. Nor does
it reject a separately specified compression. Any such change must price all
retained ages, joins, residual treatment and readouts, not just the `n^2` core.
At rank `r`, the generic triple alone has transport `3*M(n,n,r)` and nonfinal
query `3*M(n,r,n)` where `M(x,y,z)=x*z*(2*y-1)`; reducing the two U matrices
requires its own rank/indefinite-factor policy. Rank is not assumed small here.

An implementation ledger must additionally count every copy/cast, coefficients,
scalar synchronizations, baseline and changed failure path, peak co-live arrays
and kernel shapes using the supported flopscope primitives. No residual-time
forecast or 8-GiB pass has been established. A simple eigenvalue fix would add
a new approximation and cost; it is not an implicit feature of this recipe.

## 6. Independent no-label discriminator before any implementation claim

This is a proposed protocol, not permission to start measurements. Commit a
prediction and protocol first. The independent tiny oracle must enumerate the
16 labelled trees by graph edges and every dense tensor index, never reuse the
four-product H expressions. At fixed width3/4, force this branch and F21's
target contraction adapter. Use explicit signed nonconstant covariance fixtures,
nonzero means, independent unequal coordinates and a scalar-only/zero-extra
control, with no seed or labels.

Compare every equality pattern, `Htree`, anchored `H`, scalar subtraction,
discarded residual contraction, exact two-metric transport, all q slices, full
`J`, connected/raw moments, centered covariance and next complete K3 tensor.
Compare symmetric-matrix U transport with independent dense three-leg transport.
Positive controls must include zero extra input and frozen width-two behavior;
the tree closure may generate nonzero future extra state from zero incoming G,
so zero incoming G is not an assertion that regeneration remains zero.

Mutations must expose omitted path multiplicities, treating repeated labels as
one graph vertex, reusing `I` instead of transporting `M`, wrong D31 orientation,
missing U terms, wrong symmetrization normalization and missing repeated birth
subtraction. Preserve the previously proposed float64 and actual-f32 numerical
screens only after explicit registration, without changing failing thresholds.

Subsequently replay the preserved negative-variance fixture and the declared
full-depth finite/covariance/moment-matrix checks. An algebra pass validates this
approximation's implementation only. A positivity or derivative-amplification
failure stops this recipe; selecting a repair from the failure requires a new
intervention. Useful accuracy and cost would still need a complete counted
program and fresh paired evidence, with the full baseline/noise/failure protocol.

The remaining question is now narrower: **can this precisely defined regenerated
core and its persistent feed be implemented below the cost limit while remaining
admissible and useful?** The symbolic response is complete; the affordable and
stable realization is not. Preserve F21 and the ongoing representation work
while an independent review decides whether the four-product contraction and
feed decomposition justify that next bounded engineering step.
