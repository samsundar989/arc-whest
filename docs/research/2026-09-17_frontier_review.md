## Decision

The strongest next slice is **identify the differing nonlinear closure and source approximation at a shared incoming state, establish their effects in our recurrence, then implement ordinary shared-basis old-source storage without a dense merged core**. The concurrent source audit found a concrete 25-versus-62+4 term-program difference, including live final-mean products, and different protection of feed terms before compression; see the architecture review. Start there rather than searching for another isolated fourth-order patch or a universal compression theorem.

This is a credible route toward a materially better next release, not an identified winning architecture. The near-term architecture is a coherent selected cumulant recurrence with exact recent sources and older sources retained in shared coordinates. The still-unproven winning frontier is cheaper accurate queries of the old-source aggregate, additional useful closure content, or both.

The claim that the gap is *almost certainly* K3 source handling is stronger than the experiment proves. The whole fourth-order transplant failing on our trajectory rejects that transplant; it does not distinguish a K3 implementation error from a different term program, approximation policy, range finder, or cancellation among coupled errors. Isolate the first divergent operation before selecting one explanation.

## Repair the shared-state diagnostic before implementing it

**A moment state is not a probability law.** Equal mean, covariance, full K3 and a selected K4 core do not uniquely specify the exact expectation after ReLU. Therefore the proposed diagnostic can answer “which implementation or selected closure operation differs?” It cannot automatically answer “which output is physically exact?” An exact numerical reference requires a specified realizable law, such as the existing scale-mixture or quadratic-Gaussian fixtures, or a separately justified integration reference.

A scalar counterexample makes the distinction concrete: a standard Gaussian and a variable equal to zero with probability 2/3 and to each of ±sqrt(3) with probability 1/6 have identical first four moments (0, 1, 0, 3). Their expected ReLU outputs are respectively 1/sqrt(2π) and sqrt(3)/6. This is direct algebra; no experiment or external distribution-fitting claim is involved.

Use two complementary checks:

1. **Algebraic common-state check.** Normalize pre/post activation convention, covariance versus raw second moment, Wick normalization, diagonal masking, transpose direction, symmetrization factors, dtype, full-rank versus truncated residuals, and every enabled term. Run each operation on the same explicit numerical state. Compare inputs, transported slices, nonlinear term outputs, cumulant conversion, newborn tensor, and next-weight contraction separately. Start at the earliest differing canonical boundary, not solely layers 4–8.
2. **Effect in the actual recurrence.** After finding a difference, change only that operation in our implementation; compare its effect along both frozen trajectories before an end-to-end DESIGN read. A nonzero one-step difference is neither a bug nor a promotion. A single state swap can also be off-trajectory, so run reciprocal states and record which boundary is shared.

A small dense representation is appropriate for algebraic parity. It need not reproduce the 1024 score gap to detect an implementation mismatch, but a small-width *performance* effect does require a live-shape check before selection. Do not force a dense 1024-cubed tensor merely to compare two implementations: common synthetic factor states and a fixed set of exact queried entries/contractions can test the same algebra at live shape with bounded memory. The representation adapter must itself reconstruct each implementation's output on tiny fixtures before being trusted.

Freeze a term ledger rather than patching table rows by intuition: each retained coefficient, argument, multiplicity, diagonal convention and destination gets an entry. Candidate term programs that intentionally differ should be compared as different closures, not incorrectly required to match.

## Next release architecture and bounded fallback

Once the base discrepancy is attributed, pursue a separately tracked shared-factor implementation:

- Keep recent source legs in the existing exact form.
- Move old legs into a transported common basis but retain their per-source factor matrices and thin residual/feedback terms.
- Sum contributions in reduced coordinates before the one common final expansion where the algebra permits.
- Preserve the birth/consume consistency established by the common-state tests.
- Price basis selection, new-source joins, all factor updates, reconstruction, queries and temporary memory under the actual meter. Use target-shape pricing before the truth screen.
- Keep age/rank schedules as a small predeclared design, with a frozen candidate and fresh confirmation if selected/fitted. Public author constants remain local diagnostic settings.

This is not “N1 again”: it does not construct a dense r-by-r-by-r aggregate core. It is a plausible bridge to the known better public family; that family still does not equal the current leader.

If correcting the base does not improve score, the fallback is not a global rewrite. Establish a clean independently implemented common mathematical interface and compare two coherent closure programs on it, using our own fitted constants where needed and the existing provenance rules. This makes a complete joint mechanism test interpretable. It also avoids endlessly moving one term into a trajectory on which that term is not beneficial.

Only after the shared-factor candidate is measured should a two-day aggregate-query prototype be considered. The specific question is whether a compressed quadratic feature map can answer the **sum** of D3/D21 contributions more cheaply, preserving signed cancellation, than source-by-source reconstruction. It must include a join, a basis change, the current query, one subsequent dense transport, and nonlinear feedback. A sketch that preserves today's repeated slices but fails after tomorrow's weight matrix is inadequate. Retain exact tiny fixtures and measure normalized perturbation of final outputs against the uncompressed recurrence, not just tensor energy. Stop before truth if the required feature width or update price erases the saving. This is an unvalidated mechanism proposal already foreshadowed in September 16, not a new theoretical result or permission to reopen an old closed lane without a contract.

- A materially better next submission and a winning architecture are separate milestones. The public reference supplies a reproducible nearer benchmark; outperforming it still leaves a substantial leader gap.
- The live board must be refreshed by the parent review; this literature audit supplies no new rank or score snapshot.
- Internal mechanism reimplementation is already authorized in PROVENANCE_504aldo.md. Preserve the no-public-file-packaging rule and provenance ledger; do not spend another slice re-asking the withdrawn organizer question.
- Do not redirect the whole effort to the write-up simply because the named patches failed. There remains a concrete, discriminating comparison and an independently supported shared-factor implementation that the current worker summary has not completed.

The key change in plan is to make **operator attribution and a coherent base** the next deliverable. Mathematical term completeness alone, a lower tensor error alone, and a cheaper primitive alone have each proved insufficient; the next slice must connect all three to paired final score.
