# Pre-submission optimization review: Gaussian triangle alignment

Prepared September 28, before any GPU run of `tools/k111_triangle_probe.py`. This is a diagnostic under the updated PLAN B4, not an estimator candidate, a cost measurement, or a score improvement claim.

Hypothesis: a selected omitted connected Gaussian diagram contributes a predictable component of the all-distinct third-cumulant error. For source pre-covariance `C ≈ U Uᵀ`, the quadratic-Hermite triangle is `T_ijk = f2_i f2_j f2_k C_ij C_jk C_ki`, where `f2 = φ(μ/σ)/σ`. Its coefficient is **+1**: eight connected Wick pairings cancel `(1/2)^3`. The architecture and literature agents independently confirmed the coefficient and source repeated-index compensation. This is only one term in the connected expansion.

Probe: FIT full rows 0–1, source layers 2, 5, 8, 11, 14, covariance ranks 4 and 8. Use the full symmetric pre-covariance, including its variance diagonal, and its leading positive eigenmodes. Build small symmetric matrices `H_i = f2_i u_i u_iᵀ`; transport them with the next layer's weights. Trace contractions produce the next D3 and D21 slices. Subtract all source repeated-index contributions using the already-verified `rep3`/`rep21` identities; zero the next D21 diagonal only after that subtraction. Compare the resulting all-distinct term to label AD minus actual model-tower AD. The existing S2t3 final parameter file makes the baseline v71-equivalent, not v72's additional transport gates.

Report both the theoretical coefficient 1 and dot-optimal scalar fit. Report the component orthogonal to the current model AD, as well as the full residual. Orthogonal diagnostics project both the target and the triangle off the old model; their coefficient-one result includes an adjusted model-parallel component. Only the raw column tests the unchanged additive triangle. Leave-one-network-out scalar transfer is a diagnostic using the other FIT network; it is not unseen validation. Reuse the available independent K21 label replicate to check sign/alignment stability. Keep raw Gram values so decisions can be recomputed without rerunning networks. No change to the running estimator state and no label-informed correction is inserted into it.

Prediction: the rank-8 term may explain at least 5% of late-layer orthogonal D21 error energy with a positive cross-network coefficient, but the unfitted theoretical coefficient may overshoot because the fitted baseline already compensates some missing physics. This is deliberately uncertain. Stop this selected triangle route if both ranks remove under 1% of orthogonal error even with oracle scalar at all source layers 8, 11, 14, or if sign/alignment disappears on the independent K21 replicate. A positive scalar/energy result only justifies a bounded downstream test with repeated-slice consistency; it does not justify shipping or a broad fit.

Correctness checks completed before launch: `cpu_check.json` records dense float64 tensor comparisons for 6×7/q3, 7×5/q4, and 5×6/q5. Trace tensor equals the coefficient-one covariance cycle to at most 4.55e-13 absolute. Compensated D3/D21 match direct contraction of an all-distinct-masked tensor to at most 2.48e-13 relative. Both omitting repeated compensation and transposing the repeated slice fail by large factors. D21's pre-zeroed diagonal matches D3. Orthogonal projection removes an exactly model-parallel feature. The script compiles. The CPU check does not load labels, initialize CUDA, or evaluate a network.

Optimization review: stream one network and one layer, no cached tower history, no training graph (`torch.no_grad`), no loader workers/prefetch, two host threads. Reuse the existing weight cache and label artifacts; generate no labels. The only new factor arrays are O(nq²), with q ≤ 8; the largest mathematical objects remain 1024² float64 matrices. Full eigendecomposition of one 1024² symmetric covariance is shared between q4 and q8. Source model AD and label parts are computed once per selected layer and reused for both ranks. Save only small JSON scalar/Gram summaries, with an atomic per-network checkpoint; reruns reuse completed networks only when the source/parameter/probe metadata matches. No new copies of the complete dataset and no n³ tensor in the real run. The tiny test alone materializes n³ with n ≤ 7.

The comparable streaming feature probe measured 4.48 GiB peak CUDA allocation for one network and used the same Diag/twin/labels; this probe removes its feature stack and large basis projection work, adding only small q² factors and existing slice contractions. Preserve the 16 GiB host declaration because short queue samples do not reliably measure dataset initialization peaks. If the first measured run disproves the envelope, retain correctness and adjust the request; do not underdeclare resources or bypass the queue.

Independent architecture review of the implementation found no blocking sign, index, source-to-next, state-mutation, or persistent-state-cache issue. Tiny torch-CPU and numpy implementations also agree, with CUDA confirmed uninitialized during that check.
